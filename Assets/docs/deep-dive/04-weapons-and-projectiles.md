# 武器与投射物：怎么落地

## 要解决的问题

自动战斗要求武器自己找目标、自己开火，还要支持两种完全不同的形态：远程发射投射物、近战扇形判定。同时一局里有五六个持有者同时在开火（玩家加四个旅伴），投射物可能同时存在几百发。

## 落地步骤

第一步，分三层：配置、模型、行为。

`WeaponDef` 是配置表里的数据（伤害、冷却、射程、弹道数、散布角、投射物速度、穿透）。`WeaponModel` 持有运行时状态（冷却计时、已经开了几枪）。`IWeaponBehaviour` 决定这一枪怎么打出去。

第二步，用配置字段选择行为，而不是用代码分支。

```csharp
public const string RangedBehaviourType = "Ranged";
public const string MeleeBehaviourType = "Melee";
```

`WeaponDef.BehaviourType` 是权威，`WeaponDef.Kind` 只做一致性校验，写岔了直接抛异常。静默退回 `Kind` 会让"表里改成近战却还在放箭"这种错误一直藏到美术做完才发现。

第三步，开火条件按"先看有没有目标，再看冷却"。射程外不开火，也不要空放吃掉冷却——射程外 30 步后把靶子挪进射程，下一 tick 就该开火。

第四步，伤害在开火瞬间算好，写进 `DamageInfo`。

```
基础伤害 × (1 + 攻击力) × 暴击倍率 × 距离衰减
```

护甲留给 `DamageResolver`，武器层不重复实现一遍护甲曲线。暴击一次扳机掷一次，同一枪的多发弹道同暴击；如果每发各自暴击，发穿透箭打三个目标会看到三个自相矛盾的伤害数字。

第五步，投射物用定长槽位数组，不是 GameObject 池。

```csharp
struct Slot
{
    public Vector2 Position, Velocity;
    public DamageInfo Damage;
    public int RemainingHits;
    public int Stamp;
    public float Traveled, MaxDistance;
}
```

每发分配一个递增 `Stamp`，命中时写进 `_hitStamp[enemySlot]`。判断"本发是否已经打过这个身体"就是比较 `_hitStamp[enemySlot] == slot.Stamp`，比维护每发的命中集合省。

第六步，一步内的命中要排序。投射物这一步走了一条线段，线周围一圈格子里的敌人可能不止一个：

```
粗筛 → 线段距离精确判定 → 按"沿飞行方向走了多远"排序 → 从近到远逐个命中
```

穿透次数用尽时留下的是更远的目标，符合"箭穿人"的直觉。

第七步，近战不走投射物。挥砍开始后 0.08 到 0.22 秒是伤害窗口，窗口内对扇形内的敌人各判一次，同一次挥砍对同一敌人只结算一次。判定绑窗口时间戳，不绑冷却，否则攻速加成会让伤害凭空变高。

## 关键决定与代价

`Pierce` 定义为命中目标总数，1 表示只打第一个。这与"额外穿透数"的常见理解相反，写进注释和文档了。

`SpreadDeg` 一个字段两种含义：远程是相邻弹道夹角，近战是扇形半角。表里只有一个字段，复用它是为了避免加列。

`RangedBehaviour` 用 `SpatialGrid.QueryNearest` 索敌；`MeleeBehaviour` 用 `QueryCircle` 加角度过滤。

## 踩过的坑

池满了要返回失败而不是扩容。扩容会让内存悄悄涨上去再掉帧，压力看不见。

近战命中之前不发 `UnitDamaged`，所以砍刀打中既没有定格也没有震屏和受击变亮。远攻有、近战没有，测试只验了掉血所以没发现。补事件的时候要注意：死亡事件不要在命中路径上发，存活标记与清理归外部阶段，发早了就成了隐式时序。

距离衰减现在恒为 1.0。锁定目标一定在射程内，而 GDD 规定射程 100% 内不衰减，所以公式写了但运行时不生效。要让它有用得让索敌范围大于射程，而验收又要求"射程外不开火"，两件事冲突，留到数值阶段再定。

## 怎么验证

`RangedWeaponTests` 12 条：7.9 米开火、8.1 米不开、射程外不消耗冷却、0.85 秒一枪、穿透 1 与 2 的命中数与伤害、弹道数、散布对称、伤害公式端到端、距离衰减曲线。

`MeleeWeaponTests` 6 条：扇形内外、单次挥砍去重、伤害窗口、攻速翻倍后 6 秒总伤害 150 对 300。

## 迁移到别的项目要注意

投射物的命中检测依赖空间哈希的位置快照，顺序必须是"移动 → 重建 → 射击 → 投射物推进"。反过来会打到上一帧的位置。槽位戳记在敌人槽位被回收复用时会让同一发子弹白丢一层穿透，这是已知代价，注释里写了。
