# 空间哈希：怎么落地

## 要解决的问题

200 个敌人、每步要做三件需要"找附近单位"的事：敌人之间的分离力、武器索敌、投射物命中检测。全表遍历是 200 次距离计算，乘上每步几十发投射物就爆了。需要一种"给定一个圆，返回圈内单位"的结构，并且每步重建的成本可忽略。

## 落地步骤

第一步，定死网格参数：格子 2 米，32×32 覆盖 64 米，跟随玩家滚动。这个尺寸对应"敌人身体 0.7 米"和"索敌半径 6 到 8 米"——格子略大于身体、略小于索敌半径。

第二步，把"槽位"和"格子"分开。槽位就是单位索引，由 `Allocate()` 分配，一经分配不再变化。格子只记录"哪些槽位在这个格子里"，由一个稠密列表 `_live` 驱动重建。

```csharp
readonly List<int>[] _cells = new List<int>[1024];   // 每格预分配 8
readonly List<int> _live = new List<int>(256);       // 存活槽位
readonly List<int> _free = new List<int>(64);        // 空闲槽位栈
readonly List<Vector2> _snapshot;                    // 上次重建时的位置
readonly List<int> _denseIndexOf, _cellOf, _cellSlotPos;
readonly List<bool> _allocated;
```

第三步，`Rebuild(center, source)` 每步整表重建。清空 1024 个格子，遍历 `_live`，从 `source.PositionOf(slot)` 读位置存进快照，算格子下标，塞进去。滚动就是换一个 center 再调一次，没有增量更新。

第四步，`QueryCircle` 是"方格子粗筛 + 圆精确过滤"。

```csharp
// 由圆心与半径算格子范围，再逐格遍历
if ((_snapshot[slot] - center).sqrMagnitude > sqrRadius) continue;
```

结果**追加**进调用方持有的 `List<int>`，返回本次追加数量。容器复用是这条路径每步被调几百次还保持零分配的前提。

第五步，`QueryNearest` 做环形扫描，由近到远一圈圈找，找到就返回，没有返回 -1。

## 关键决定与代价

槽位号固定不变，是这套结构最重要的约束。移除走两次末尾交换：格内列表把最后一个换过来，稠密列表也把最后一个换过来。别的单位编号不会前移，所以外部按槽位存的数组（敌人的 `EnemyModel[]`、投射物的命中戳记）不用跟着搬。

查询返回上一次重建时的位置快照，而不是实时位置。这样同一 tick 里"谁先查"不影响结果，固定种子才能复现。代价是位置滞后一个重建周期，正好对上"移动完再重建"的顺序。

不用四叉树也不用物理引擎：200 单位、场地固定，散一轮就是遍历 200 个槽位，实测 7.1 微秒，维护树结构不划算。

## 踩过的坑

格子是方的，圆查询必然多带进角落里的单位，所以粗筛之后必须再做一次精确距离过滤，省掉这一步会打出"擦着边没碰到也掉血"。

查询结果里可能留着两次重建之间已被移除的槽位，调用方用之前要问 `IsAllocated(slot)` 或者查自己的数组。

`QueryCircle` 一千次在 8 米半径下是 2.8 毫秒，超出原定的 0.5 毫秒。原因是 2 米格子配 8 米半径要扫 9×9 格，成本几乎全在空格子上。这一点没改结构，因为实际索敌受武器冷却限制，不是每帧一千次；把偏差写进了 `perf-log.md`，等 I1-11 的真实压力数据再定。

## 怎么验证

`SpatialGridTests` 9 条：半径内命中、跨格命中、半径外不命中、移除后查不到、末尾交换后其余槽位仍正确、滚动后仍正确、`QueryNearest` 空网格返回 -1。

性能在仓库外 harness 里量：200 单位重建 7.1 微秒（avg），1000 次查询按半径分档记录。bench 不进 EditMode 测试，避免 CI 抖动假红。

## 迁移到别的项目要注意

格子大小要同时满足"大于大多数单位身体"和"小于最小查询半径"，两头都不满足时这套结构会退化。槽位复用要配合戳记或版本号，否则"上一发子弹打过这个槽位"和"这个槽位现在是另一个敌人"会混在一起。
