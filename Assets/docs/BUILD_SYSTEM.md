# 构筑系统设计

配套：[游戏设计文档](GDD.md) · [技术方案](TECH_DESIGN.md)

本文只回答一个问题：**一局 10 分钟里，玩家靠什么变强、为什么每一次升级都值得做选择。**

---

## 1 设计目标

| 目标 | 具体含义 | 反例 |
|---|---|---|
| 每 20–40 秒有一次变强 | 经验节奏 + 升级抽卡，不靠回城/商店 | 打完一整段才给一次奖励 |
| 四条主干都能独立撑起一局 | 武器、旅伴、数值、buff 都能赢，不是"数值卡永远最优" | 只有攻击力一条线 |
| 选择有代价 | 武器槽 4、旅伴 4、每张卡有叠层上限 | 全部都能拿满 |
| 前期能成型，后期能极限 | 前 3 次升级大概率给武器/旅伴；后期稀有度上浮 | 一上来就金卡，或 10 分钟还是白卡 |
| 构筑可读 | 玩家能在 HUD 上看到武器数、旅伴数、等级、威胁 | 只能靠记忆 |

设计红线沿用 GDD：一张卡最多同时给两项收益；所有随机可复现；强度曲线写在表里。

---

## 2 单局循环

```
进入 Run（角色 + 起始武器）
  → 战斗：自动开火 / 移动 / 冲刺，导演按时间刷怪
  → 击杀掉经验 → 拾取 → 经验满
  → 暂停，三选一构筑（可重抽 1 次）
  → 回到战斗，继续刷怪/变强
  → 10:00 时间到，BOSS 出场
  → 击杀 BOSS = 通关；死亡 = 结算
```

一局只有一条时间轴。没有波次、没有商店、没有金币。经验是唯一的经济，构筑是唯一的成长。

## 3 四条构筑主干

### 3.1 武器（Weapon）

- 槽位：`WeaponSlots = 4`（Balance）。
- 等级：`WeaponMaxLevel = 5`（Balance）。
- 每级：伤害 ×(1 + 0.30)，间隔 ×0.92。
- 里程碑（仅远程武器）：Lv3 额外 +1 弹道，Lv4 额外 +1 穿透；近战不消费这两项，卡面也不显示。
- 卡池：同一张武器卡既可以是"新武器"也可以是"升级"，由当前是否持有决定，不另做两套卡。
- 起始武器占用一个槽位；满槽后武器卡只出升级，不再出新武器。

武器不是"数值皮肤"：远程/近战、单发/多弹道/穿透/全向，四种手感由 `WeaponDef` 的 `Kind / Projectiles / SpreadDeg / Pierce / Params` 决定，加武器只加一行表 + 必要时加一个行为类。

场景内每把已装备武器都有独立模型与动作：`WeaponVisualStyle` 定六种攻击类型、槽位、拖尾与配色，`WeaponVisual` 用内置几何体拼模型并按 `ShotsFired` 播放挥砍/拉弓/后坐/脉冲。玩家最多四把围绕胶囊槽位，用 `SmoothDamp` 追玩家身后形成拖尾；旅伴只有一把，按体型缩小。表现层不参与伤害判定；升级卡面目前仍是文字，卡牌图标/预览属于后续工作。

### 3.2 旅伴（Companion）

- 队伍上限 4（`CompanionSystem.MaxCompanions`）。
- 每个旅伴 3 级，重复拿同一个 = 升级：伤害 +40%/级，间隔 ×0.92/级。
- 阵营：机械 / 幽灵 / 野兽 / 玩偶。2 件、4 件触发羁绊（沿用 `CompanionBonds`）。
- 旅伴卡与武器卡分开计数，但都受"槽位"约束：队伍满了就不再出新的旅伴卡，只出已有旅伴的升级卡。
- AI：`Follow` 阻尼环绕玩家（目标点随移动方向轻微拖尾）；`Aggro` 主动贴敌；`Kiter` 保持距离；`Guard` 只打靠近玩家的敌人。所有 AI 受 `LeashDistance` 限制。

羁绊是构筑的第二层：玩家可以为了 4 件机械去拿两个不想要的机械旅伴，也可以保持混搭吃更多独立加成。4 件不是无脑最优——它要求牺牲两个槽位。

### 3.3 数值（Stat）

- 直接写进 `StatBlock` 的永久修正，按 `UpgradeDef.MaxStacks` 叠层。
- 目前 14 张：攻击、攻速、生命上限、移速、暴击率、暴击伤害、射程、拾取、护甲、生命回复、远程弹道 +1、幸运、碰撞伤害、闪避。
- 数值卡是"稳定器"：不改变玩法，只让现有构筑的曲线更顺。它的权重最高（`BuildWeightStat = 32`），但不应该压倒武器/旅伴。

数值卡的两个注意点：

1. 攻击力/攻速/暴击率/弹道/射程的 `StatBlock` 基线是 0，它们的值本身就是"加成比例/额外发数"，所以卡面用 `Flat` 写 0.10，而不是 `Percent`（Percent 乘 0 还是 0）。
2. 生命上限、移速有非零基线，用 `Percent` 才有意义。

### 3.4 buff 道具（Buff）

buff 是"带触发条件的构筑件"，不是一次性消耗品。获得时先写 `BuffDef.StatA/StatB`，再按 `Effect` 挂触发：

| 触发 | 行为 | 例子 |
|---|---|---|
| `Stat` | 只写属性 | 玻璃大炮：攻击 +25%，生命上限 −15% |
| `OnKillAttackSpeed` | 每次击杀叠一层攻速，有上限 | 疯狂：+2%/层，最多 20 层 |
| `OnKillHeal` | 每次击杀回固定生命 | 血袋：1.5/击杀 |
| `OnHurtArmor` | 每次受击叠一层护甲 | 疤痕护甲：+2/层，最多 15 层 |
| `LowHpAttack` | 生命低于阈值时加攻，回到阈值以上移除 | 背水一战：<35% 时 +35% |
| `PeriodicHeal` | 每隔 Interval 秒回血 | 再生：每 5 秒 2 点 |
| `OnKillExplode` | 击杀时尸体位置爆炸 | 燃烧弹 |
| `OnHitExplode` | 命中时目标位置爆炸（有冷却） | 过载组合 |
| `OnHitChain` | 命中时向附近敌人弹射闪电 | 导电 |
| `OrbitDamage` | 玩家周围周期伤害 | 环绕刀 / 旋风 |
| `Lifesteal` | 造成伤害按比例回血 | 吸血獠牙 / 血契 |
| `OnHurtThorns` | 受击时对周围敌人反伤 | 荆棘甲 |

buff 的强度来自"条件"：疯狂要不停击杀、疤痕要挨打、背水要压血。它们把"怎么打"写进构筑，而不是只加一个数字。

机制道具（燃烧弹/导电/环绕刀/吸血獠牙/荆棘甲）是"行为型"构筑：它们直接改变命中、击杀、受击、每步结算，不再只是加一个百分比。

## 4 品质、权重与抽卡

### 4.1 品质

| 品质 | 颜色 | 使用场景 |
|---|---|---|
| Common | 白 | 前期主力，稳定但上限低 |
| Rare | 蓝 | 中期成型 |
| Epic | 紫 | 构筑核心/触发型 |
| Legendary | 金 | 高风险高回报，出现率低 |

品质只影响抽卡权重与卡面颜色，不直接进伤害公式。每张卡另有自己的 `Weight`，用于同类内部排序。

### 4.2 抽卡算法

每次升级：

1. 过滤不可用卡：
   - 武器：满槽且未持有 → 不可用；已持有且满级 → 不可用。
   - 旅伴：满队且未持有 → 不可用；已持有且 3 级 → 不可用。
   - 数值/buff：已拿满 `MaxStacks` → 不可用。
2. 对剩余每张卡计算 `权重 = UpgradeDef.Weight × 类别权重 × 品质倍率`。
3. 不放回地抽 `OfferCount` 张（Level 表配置，默认 3，10/20 级 4 张）。
4. 卡池不足时少给，不重复。

品质倍率：

```
Common    1.00
Rare      0.60
Epic      0.20 × (1 + 2 × bonus)
Legendary 0.04 × (1 + 4 × bonus)
bonus = LevelDef.RarityBonus + Luck × 0.01
```

`bonus` 从 0 到约 1.4：1 级几乎只见白蓝，10 级后紫开始常见，金仍然是稀有事件。幸运属性是"把稀有度往上推"的第二个旋钮。

类别权重（Balance）：

```
武器 30 / 旅伴 18 / 数值 32 / buff 与机制 22
```

这组数是刻意让数值卡保持稳定器地位，同时把机制道具的比例抬上来：武器和旅伴决定玩法，数值保证曲线，机制提供"这一局怎么打"的差异。

### 4.3 组合效果

每张构筑卡带 `Tags`（如 `ranged / melee / crit / attackSpeed / explosive / chain / lifesteal / orbit`）。
拿卡时累计标签，达到 `Combo` 表条件就自动获得组合 buff，不占槽位、不占卡池，一局只触发一次：

| 组合 | 条件 | 效果 |
|---|---|---|
| 过载 | 爆炸 + 闪电 | 命中引发范围爆炸（OnHitExplode） |
| 血契 | 吸血 + 暴击 | 吸血比例提高（Lifesteal） |
| 弩阵 | 2 远程 + 穿透 | 弹道 +1（Stat） |
| 旋风 | 2 近战 + 攻速 | 环绕刀（OrbitDamage） |

组合的作用是给"拿卡路线"一个额外奖励：玩家可以为了过载去拿两张平时不一定优先的机制卡，也可以保持混搭。

### 4.4 重抽

每次升级免费重抽 1 次（`RerollsPerLevel`）。重抽不改变品质保底（没有保底），只重新抽同一轮。

不做"锁卡/ban 卡"：这一版的控制手段只有重抽，避免 UI 与规则同时膨胀。

## 5 等级与节奏

`Level` 表 30 行，`XpToNext` 逐级复利增长（约 1.16×），`OfferCount` 默认 3，`RarityBonus` 从 0 线性升到 1。

| 阶段 | 时间 | 等级（目标） | 玩家体验 |
|---|---|---|---|
| 开局 | 0:00–1:00 | 1–4 | 拿第一把副武器/第一个旅伴，认识卡池 |
| 起势 | 1:00–3:00 | 4–9 | 2–3 把武器，第一次 2 件羁绊 |
| 成型 | 3:00–6:00 | 9–17 | 主武器 3–4 级，buff 开始联动 |
| 极限 | 6:00–9:00 | 17–25 | 紫/金变多，4 件羁绊或高风险 buff |
| 终局 | 9:00–10:00 | 25–30 | 满构筑，等 BOSS |

升级暂停战斗（`RunPhase.LevelUp`），所以节奏是"打一段 → 停下来做一次决定 → 继续"，不是实时弹窗。

一次拾取跨多级时，`RunState.PendingLevelUps` 排队，选完一轮立刻开下一轮，不会回到战斗再暂停。

## 6 构筑协同

设计上允许四条明确的 synergy，而不是只堆数值：

1. **攻速流**：多弹道武器（灵球/弓）+ 攻速 + 疯狂/暴怒。攻速同时放大"每发伤害"与"触发频率"。
2. **击杀流**：高击杀速度 + 疯狂（攻速）+ 血袋/吸血（回复）+ 玻璃大炮（风险）。击杀越多越强，但生命上限更低。
3. **羁绊流**：4 件同阵营 + 旅伴升级。牺牲槽位换全队加成，配合"全队"属性（攻速/伤害/生命上限）。
4. **近战碰撞流**：砍刀/战锤 + 碰撞伤害 + 护甲/回复。需要贴脸，靠生存属性兜底。

反例：不允许"一张卡同时给伤害、生存、经济"；不允许"拿到就无敌"的卡。金卡也要有代价（玻璃大炮、背水一战）。

## 7 数值与验收

| 项 | 目标 | 验证 |
|---|---|---|
| 一局时长 | 10:00 + BOSS | `RealRunFlowTests`（真实配置 36000 步） |
| 升级次数 | 20–30 次 | 同上（当前 29 次） |
| 前 3 次升级有武器/旅伴 | ≥1 张 | 抽卡权重 + 可复现测试 |
| 满级 | 30 | Level 表 30 行 |
| 同屏 | ≤ 导演上限（120 + BOSS 召唤） | 同上（当前 101） |
| 武器槽 | 4 | `WeaponSlots` |
| 旅伴 | 4 | `CompanionSystem.MaxCompanions` |
| 卡池 | 每类至少 6 张 | `Upgrade.json`（43 张） |
| 机制 | 至少 5 个行为型道具 + 4 个组合 | `Buff.json` / `Combo.json` |

调参顺序：

1. 先调 `Level.XpToNext`：决定"多久做一次选择"。
2. 再调 `Director` 的 `SpawnInterval/SpawnCount/Cap/HpScale`：决定"压力是否跟得上"。
3. 最后调单卡 `Weight/Value`：决定"哪条流派更强"。

不要在代码里写死任何成长倍率；所有曲线必须在 `Level` / `Director` / `Balance` / `Upgrade` 表里可查。

## 8 扩展方式

- **加武器**：`Weapon` 加一行 → `Upgrade` 加一张 `Category=Weapon` 的卡。需要新行为时才加 `IWeaponBehaviour` 实现。
- **加旅伴**：`Companion` 加一行（阵营 + 武器）→ `Upgrade` 加一张 `Category=Companion` 的卡。羁绊自动按阵营统计。
- **加数值卡**：`Upgrade` 加一行 `Category=Stat`，填 `StatA/ValueA/OpA`。不需要改代码。
- **加 buff**：`Buff` 加一行 → `Upgrade` 加一张 `Category=Buff`。已有 `Effect` 类型可以直接复用；新触发类型才加一个 `BuffEffectType` + `BuffSystem` 分支。
- **加敌人**：`Enemy` 加一行，`PrefabId` 可以复用已有几何体；`Director` 的 `EnemyPool` 决定它从哪一段开始出现。

## 10 设计检查清单

新增/修改一张卡时逐条过：

- [ ] 它属于四条主干中的哪一条？如果说不清，先别加。
- [ ] 它是否同时给"伤害 + 生存 + 经济"？是就拆开。
- [ ] 它的上限是多少？满层/满级后会发生什么？
- [ ] 它在前期是否过强、后期是否完全没用？用 `Rarity` 与 `Weight` 调，不写死在代码里。
- [ ] 它和现有哪条 synergy 联动？如果没有任何联动，考虑换效果。
- [ ] 它是否能在一局里被验证生效？不能验证的卡不加。
